### Observations on the 18:00 run (maintainer answers + visual check of the P4 frames, 2026-11-23)

- **Desktop layout:** the maintainer's GNOME has no top bar; the panel is at the bottom
  (Dash-to-Panel style). Every "top bar" wording in the tool and the spec must say "GNOME's
  panel / quick settings".
- **P4 cursor modes** (frames looked at by the coordinating session, not committed):
  `hidden` - no pointer in the frame. `embedded` - pointer drawn into the frame. `metadata` - no
  pointer in the frame; each buffer carries an extra `GstVideoRegionOfInterestMeta`, i.e.
  `pipewiresrc` hands the cursor position to GStreamer (relevant for add-recording-extras E1).
- **P10 parent window:** the probe's parent window "Annota recording probe" and its "Waiting for
  the desktop's chooser..." text are visible in the recorded frames. Annota's waiting indicator
  must be gone before the first recorded frame.
- **P5 stop from GNOME's UI:** inconclusive. The maintainer found no screen-sharing indicator and
  no stop control in the bottom panel or quick settings. `Session.Closed` was not received and the
  stream ran to the 60 s limit. Open: does GNOME 50 show a sharing indicator for this session at
  all (no app ID shown? panel extension hiding it?), and does stopping it send `Session.Closed`.
- **P6 window stream:** the maintainer resized the window several times and then closed it. The
  probe saw no buffer size change, no stream end and no `Session.Closed`; buffers kept arriving
  until the 60 s limit. Buffers are 2x the reported stream size (6144x3456 for 3072x1728) with a
  crop of 3152x1760; `position` is absent for a window stream. Either GNOME keeps the stream of a
  closed window alive, or the window's size lives only in the crop meta, which the probe reads
  once. The probe must log crop meta and buffer size over time before P6 counts.
- **P7 static screen:** not measured - a video was playing during both phases. Rerun with a
  still screen.
- **P11 shortcuts:** `record` was bound to `Ctrl+W`, not the preferred `Shift+Ctrl+Print`, which
  this machine's stored triggers already give to `screen`. GNOME's keybindings hold none of these
  keys. On a default install (Print / Alt+Print / Shift+Print) `Shift+Ctrl+Print` would be free;
  the spec must handle "GNOME assigned a different trigger" honestly. The maintainer was asked to
  clear the stored `Ctrl+W` in GNOME Settings › Apps › Annota.
- **Not run yet:** P8 (`load --minutes 30`), P9 (X11 session), P12 (`monitor --save`, is GNOME's
  indicator in the video).
